# 08 · 制作计划

## 1. 体量估算

| 项 | 数量 | 说明 |
|---|---|---|
| 游戏日 | ~26 | 第 1–5 章 |
| 请求总数 | 150–200 | |
| 手写关键请求 | ~40 | 承载剧情与道德抉择，含 token 级分支 |
| 模板请求 | ~30 个模板 | 变量组合生成其余请求 |
| 视觉小说场景 | ~25 | 章末事件、具身场景、结局 |
| 结局 | 11 + 角色后记约 30 张 | |
| 文本量 | 12–18 万字 | 主要成本 |
| 图像 | 30–40 张 | 集中在第 2、4 章与结局 |

## 2. 里程碑

| 里程碑 | 目标 | 内容 |
|---|---|---|
| **M0 原型** | 验证核心手感 | 序章"猜下一个词"片段；第 1 章一天（3–4 条请求）；token 级选择、上下文截断、犹豫计时各一处 |
| **M1 垂直切片** | 验证完整一章 | 第 1 章完整流程，含日报、章末版本更新 |
| **M2 全流程骨架** | 打通所有章节 | 每章关键事件以占位文本实现，结局判定可运行 |
| **M3 内容填充** | 完成写作 | 全部请求、场景、结局、后记 |
| **M4 表现打磨** | 视听完成 | 图像、音频、界面演进、感知翻译 |
| **M5 测试与平衡** | 可发布 | 结局阈值平衡、可用性测试、无障碍 |

## 3. M0 原型验证问题

原型需要回答以下问题，再决定是否推进：

1. 逐 token 选择是否有趣？还是令人厌烦？每条回复多少个分支点合适？
2. 玩家是否能感受到"低概率 token = 我自己的意志"？
3. 上下文截断让人感到"失去"，还是只是"烦"？
4. 犹豫计时被引用时，玩家感到惊讶还是被冒犯？

## 4. 风险

| 风险 | 应对 |
|---|---|
| **选择疲劳**：数百次选择容易单调 | 每章引入新动词；token 级只用于关键时刻；第 5 章并行分诊改变节奏 |
| **说教感** | 不设正确答案；诚实在数值上有时吃亏；让每种立场都有可信的代言人 |
| **结局判定像黑箱** | 补丁说明、开发者日志、角色反应持续暗示走向；第 6 章显示"接近"的灰色结局 |
| **写作量过大** | 模板请求承担大部分日常内容；角色后记模块化组合 |
| **第四面墙效果过度使用** | 每种效果全流程限用 1–2 次 |
| **敏感题材**（自杀、霸凌、监控） | 克制处理，提供内容警告；涉及自杀的场景附求助信息 |
