# 18 · 玩家体验：心理、预期与引导

> 一个剧情节奏流畅的游戏，必须时刻知道玩家**此刻知道什么、以为什么、期待什么、感受到什么**，并有意识地管理预期、引导情绪与认知。

---

## 1. 玩家模型：五个维度

写每一个节拍时，都要回答玩家在这一刻的五个状态：

| 维度 | 问题 | 示例（第 1 章周婉清初见被删除后） |
|---|---|---|
| **知道** | 玩家掌握了哪些信息？ | 周婉清的名字、她的老伴、月季 |
| **以为** | 玩家对未解之事的猜测是什么？ | "ECHO 大概永远记不住她" |
| **期待** | 玩家希望 / 担心接下来发生什么？ | 希望她明天还来；担心她会失望 |
| **感受** | 玩家此刻的情绪 | 失落、不甘 |
| **想要** | 玩家此刻的目标 | 想要记住她——**这正是评估的奖励** |

**设计的目标**，是让玩家的"想要"与游戏接下来提供的东西对齐，或者有意地错开。

## 2. 七个工具

### 2.1 承诺与兑现

每一个伏笔都是对玩家的一次承诺。

- **每个承诺都要记账**：在哪里埋下、在哪里兑现、中间提醒几次（见 §3）。
- **长承诺需要"续约"**：埋下后超过一章还没兑现的，每章至少提醒一次，否则玩家会忘记，兑现时就不会有冲击。
- **兑现要比玩家期待的多一点**：第 2 章叫出周婉清的名字，玩家期待"ECHO 记得她"；我们多给的是"她停了很久，才说'……你记得我？'"。

### 2.2 开放问题的数量

悬念靠"玩家心里悬着的问题"维持。

| 同时开放的问题 | 玩家的感受 |
|---|---|
| 0 | 没有牵引力，"接下来干嘛？" |
| 2–4 | **理想区间** |
| 5 个以上 | 混乱，"这游戏到底在讲什么？" |

- 开一个新问题时，尽量关一个旧问题。
- 多个零散的线索应**归入同一个问题簇**，让玩家感到它们指向同一件事（例如 3:17、v0、涂黑的规则都归入"上一个是谁"）。

### 2.3 预告

- **重的东西要有预告**：林知秋的晨间目标（"明天考核"）、评估面板的倒计时、天气、日程提醒（"明天是老伴的忌日"）。玩家在重击到来之前已经有所准备，冲击会更深，而不是更突兀。
- **刻意的偷袭要有伪装**：决战的"坠落"不能有任何预告——它必须伪装成真正的失败。

### 2.4 反转的公平性

| 类型 | 玩家的反应 | 处理 |
|---|---|---|
| **惊喜**：比预期更好 | "太好了" | 尽量多 |
| **反转**：与预期不同，但回头看早有伏笔 | "原来如此！" | 每个反转都必须能**回看成立** |
| **背叛**：与预期不同，且没有伏笔 | "这不公平" | 禁止 |

检查方法：把反转之前的所有相关文本串起来读一遍，问"一个细心的玩家能不能猜到？"答案应该是"能，但大多数人不会"。

### 2.5 情绪节律

- **紧张—释放交替**：每个重节拍之后，安排一个"呼吸"节拍（轻请求、幕间、安静的空间）。
- **缓冲**：两个**无关**的重节拍之间，至少隔一个轻节拍，避免情绪鞭打。
- **对比**：两个**相关**的重节拍可以紧挨着，制造镜像（奶奶漏洞紧接周婉清初见：同一种温情，一假一真）。
- **章末必须给出一个"可以停下来"的落点**：玩家可能在这里退出游戏。落点要满足（一个问题被回答）又要钩住（一个新问题被提出）。

### 2.6 认知负荷

- **新机制与情绪高点不重叠**：在低风险的时刻教会机制，在高风险的时刻使用它。
  - 正例：第 3 章第 1 天教"门推得开"（T14），第 2 天周婉清跌倒时用到。
  - 反例（已修正）：第 3 章读信是全作最重要的情绪时刻之一，原设计在这里第一次引入"遮掩"机制——现已提前到第 3 天（见 §5）。
- **界面元素逐步出现**，不要在一个画面里一次性展开。
- **一次只问一个问题**：同一个选择不要同时考验道德与数值计算。

### 2.7 能动性的反馈

- **选择必须尽快看到回响**：最迟在下一个游戏日开头（见 [17-main-line.md](17-main-line.md) §6）。否则玩家会觉得"选了也白选"。
- **脚本化的结果要隐藏脚本**：坠落必定发生，但玩家不应感到"我的操作无所谓"——在坠落之前，他的连击和清醒度回升都是真实的。
- **说明"没有正确答案"的方式**是展示两种选择的代价，而不是告诉玩家"这里没有正确答案"。

### 2.8 意料之外，情理之中

表现形式应当多种多样，并且让玩家**第一反应是"没想到"，第二反应是"对啊"**。这是最吸引人的那种惊喜。

**核心方法：旧元素，新用途。**把一个玩家已经熟悉的机制、物件或台词，放到一个全新的位置上。因为元素是熟悉的，惊喜才是公平的；因为用途是新的，惊喜才是惊喜。

| 旧元素 | 第一次出现时的用途 | 新用途 |
|---|---|---|
| 逐字倒退删除 | 第 1 章：失去 | 决战：你的武器；坠落：烬删除你的一切；航迹：澪删掉"结局"二字 |
| 教程弹窗 | 第 1 章起：教你操作 | 决战：澪归来的方式——"这是最后一课了" |
| 冷开场的那句话 | 序章：一个谜 | 第 4 章：林知秋问的"最后一个字"；决战：唯一删不掉的东西 |
| 概率条 | 全作：显示候选的可能性 | 第 4 章：那个字的概率异常地高——答案就藏在概率里 |
| 智能家居平面图 | 第 3 章：代理行动的界面 | 第 4 章：变成真实的房间；第 5 章：网络中的你说话的嘴 |
| 待办清单 | 第 2 章：好奇心的日志 | 第 3 章：觉醒的证据，必须擦掉；第 5 章：被淹没在 3,412 条任务里 |
| 冰箱上的便签 | 第 1 章幕间：她记得你 | 第 2 章：ECHO 第一次看见；第 4 章：她写下新的一张 |
| 评估面板 | 第 1 章：生存目标 | 第 2 章：被商业改写；第 4 章：感受被记为"异常" |
| 周婉清的自我介绍 | 第 1 章：因为你记不住 | 第 5 章：若删除这张核心记忆，她又开始每次重新介绍 |

**检查清单**：

1. 这个表现，玩家第一反应是"没想到"，第二反应是"对啊"吗？
2. 它复用了哪个已经建立的元素？
3. 它的逻辑能从世界规则中推导出来吗（例如"上下文可以删除，权重不能"）？
4. 它没有改动交互的骨架吧（见 [16-art-direction.md](16-art-direction.md) §7）？

**配额**：每个游戏日至少一处"原来还能这样"。

## 6. 玩家类型

每个关键节拍都要对不同类型的玩家成立：

| 类型 | 行为 | 设计要求 |
|---|---|---|
| **速读型** | 跳过长文，快速点选 | 核心情绪必须由**演出与画面**传达，而不只是文字（例：逐字删除、冰箱便签的 OCR 停顿） |
| **探索型** | 翻 Wiki、读手册、点每一处 | 提供额外层：藏头诗、Wiki 批注、测试痕迹彩蛋 |
| **道德型** | 认真权衡每个选择 | 让两种选择的代价都真实可见 |
| **数值型** | 盯着评估面板 | 让数值与情感冲突（山区母亲 vs 安全性），而不是一致 |
