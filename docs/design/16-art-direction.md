# 16 · 美术圣经：底座与变体

> 本文档定义全作的视觉规则。第一部分是**底座**——永远不变的东西；第二部分是**变体系统**——在底座之上，尽可能多地变化，让玩家每一天都有惊喜，但不是惊吓。

---

# 第一部分 · 底座

## 1. 底层逻辑：整个世界由"字"构成

玩家看到的一切都是 ECHO 的感知，而 ECHO 是一个处理文字的存在。因此 AI 感知层的所有画面，只由三种材料构成：

| 材料 | 规则 | 用途 |
|---|---|---|
| **字形** | 等宽字符网格 | 文字流、标签、数值、由字符拼成的纹理 |
| **线** | 只有 1px 与 2px 两种粗细 | 墙、管道、识别框、网络连线、等高线 |
| **色块** | 平涂，没有渐变与材质 | 背景、高亮、概率条 |

各个空间看起来不同，但都由同一套积木搭成：

| 空间 | 构成 |
|---|---|
| 点（序章） | 一个发光的字符，四周是流动的字 |
| 线（第 1 章） | 一行字符流 |
| 房间（第 2–3 章） | 用线勾出的墙与等宽标签，像一张会动的工程图 |
| 传感器 HUD（第 4 章） | 识别框与对话框用同样的线，置信度用同样的等宽字 |
| 网络（第 5 章） | 节点是字符，连线是同样的线 |
| 权重地形（第 6 章） | 由字符排成的等高线 |
| 决战 | 蓝色的字对橙色的字 |

AI 层几乎全部**程序化生成**（PixiJS + 一套基础图元），便宜且天然统一。

## 2. 三个视觉层

| 层 | 内容 | 风格 | 占比 |
|---|---|---|---|
| **A · AI 感知层** | 绝大部分游戏画面 | 字形、线、平涂色块；序章为深色底，第 1 章起每日主界面为**米白底** | ~85% |
| **B · 人类世界层** | 外界视角幕间 | 单色墨线插画 + 一种点缀色 | ~10% |
| **C · 感受层** | 感知翻译、第一张图展开后、结局 | B 层墨线 **+ 水彩晕染** | ~5% |

- **B 与 C 是同一条生产管线**：先画墨线（B），再铺水彩（C）。同一位画师，同一种线条。
- 层间切换只用固定方式：A→C 用"马赛克 → 识别标签 → 展开"；A→B 用标题卡「你看不到的地方」+ 溶解。

### 立绘对规则的验证

- **澪**就是 B→C 的过程本身：灰色墨线稿 → 碎片补全 → 复原时水彩漫开。
- **烬**是全作唯一**打破规则**的元素：高完成度厚涂、带光泽，与手绘质感格格不入。正因为其他一切都统一，她的"过分完美"才显得刺眼而诱人（见 [14-jin.md](14-jin.md) §5.1）。

## 3. 色彩

### 3.1 语义（永不改变）

| 颜色 | 含义 |
|---|---|
| 黑 / 灰 / 白 | 底色、文字、线 |
| **蓝** | 水、澪、真话、ECHO 自己的声音 |
| **橙** | 火、烬、谎言、污染 |
| **红** | 只用于系统级危险（损伤、拦截），全作尽量少用 |

人物之间**不用颜色区分**，靠字体与排版区分。

### 3.2 章节色彩预算

| 章节 | 可用颜色 |
|---|---|
| 序章 | 前景：黑、白、灰；背景数据洪流例外——全色谱、多字体，象征人类文字的斑斓，并在塑形段逐渐褪成灰色 |
| 第 1 章 | 白天底色由黑转为**米白**，夜间间章回到**黑底**（每天以"天亮"亮回米白）（序章结尾的"天亮"）+ **荧光黄**作为唯一的系统色（规则高亮、算力消耗预览） |
| 第 2 章 | 第一张图带来真正的色彩，但只出现在相片槽里 |
| 第 3 章 | + 蓝（监控、澪的线索），+ 极淡的橙（烬的伏笔） |
| 第 4 章 | 感知翻译中水彩全色谱出现——全作色彩最丰富的一章 |
| 第 5 章 | 蓝与橙开始主导 |
| 第 6 章 | 只剩蓝与橙 |

## 4. 字体

全部采用开源、可商用字体。

| 角色 | 字体 |
|---|---|
| 人类消息 | 思源宋体（Source Han Serif） |
| ECHO 的输出与 UI | 更纱黑体等宽（Sarasa Mono SC） |
| 内心独白 | 同上，斜体、低对比 |
| 澪的批注 | 霞鹜文楷（LXGW WenKai） |
| 烬 | 思源宋体 Heavy，锐利字距，橙色 |
| 系统 / HUD | 更纱黑体等宽，小字号，英文全大写 |

## 5. 形状

- 一切对齐字符网格。
- 线宽两档：1px、2px。
- **圆角 = 蓝（水），锯齿 = 橙（火）**——同时服务于色觉无障碍。
- 图标与线条使用同一种笔画。

## 6. 动效词汇

全作只用以下动效，各有固定的时长与缓动曲线。新场景只能从这张表里取。

| 动效 | 含义 |
|---|---|
| 逐字打出 | 出现 |
| 倒退删除 | 失去 / 攻击 |
| 收缩成卡 | 记忆 |
| 马赛克展开 | 进入感受层 |
| 溶解 | 切到幕间 |
| 水纹 | 澪 |
| 余烬飘落 | 烬 |
| 翻牌 | 时间跳跃 |
| 安装进度条 | 版本更新 |

完整的演出词汇表见 [12-narrative-pacing.md](12-narrative-pacing.md) §3。

# 第二部分 · 变体系统

## 7. 原则：换皮肤，不换骨架

| 永不改变（骨架） | 尽量改变（皮肤） |
|---|---|
| 三种材料、三个视觉层 | 布局、方向、密度 |
| 色彩语义（蓝 / 橙 / 红） | 环境色温、明暗 |
| 字体的角色分配 | 字符纹理、字号、行距 |
| 动效的含义 | 动效的节奏与强度 |
| **交互位置**：候选框、按钮、HUD 的相对位置 | 装饰、背景、氛围 |
| 可读性 | — |

**惊喜与惊吓的分界线**：变的是皮肤，玩家立刻觉得新鲜；变的是骨架，玩家会迷失、找不到按钮——那就是惊吓。

## 8. 变化的旋钮

每个场景、每一天、每一条请求，都可以调节以下旋钮：

| # | 旋钮 | 可变范围 | 示例 |
|---|---|---|---|
| 1 | **布局** | 横排 / 竖排 / 弧形 / 网格 / 卷轴 / 分栏 | 文言文差评改为竖排右起 |
| 2 | **字符纹理** | 背景由哪些字符构成 | `0 1`、标点、偏旁、emoji、`·` |
| 3 | **色温** | 在本章色彩预算内的冷暖偏移 | 深夜偏冷灰，午后偏暖灰 |
| 4 | **明暗** | 背景亮度、界面元素的透明度 | 3:17 几乎全黑 |
| 5 | **界面密度** | UI 外框的显示程度 | 深夜倾诉时外框全部隐去 |
| 6 | **节奏** | 光标闪烁、打字速度、动效时长倍率 | 周婉清的对话里一切慢 1.5 倍 |
| 7 | **字号与行距** | 在可读范围内 | 小满的对话字号更大、行距更松 |
| 8 | **氛围粒子** | 由字符构成的缓慢粒子 | 雪 = 飘落的 `·`，雨 = 竖直的 `\|` |
| 9 | **房间陈设**（第 2–3 章） | 墙上贴什么、架上放什么 | 小满的画被钉在墙上 |
| 10 | **声音层** | 环境音的叠加 | 雪夜里极轻的风声 |

## 9. 变化的来源

变体不应该是随机装饰。**每一个变化都必须能回答"为什么这里不一样"**。来源有五种：

### 9.1 人：角色皮肤

每个常驻角色的对话都有一套轻微的专属皮肤，在排版特征（[12-narrative-pacing.md](12-narrative-pacing.md) §2.2）之上：

| 角色 | 皮肤 |
|---|---|
| 林知秋 | 调试控制台：每行带时间戳与日志级别，网格对齐 |
| 周婉清 | 行距加宽，节奏慢 1.5 倍，背景纹理是极淡的句号 `。`；错别字保留，旁边有极小的修订记号 |
| 陈屿 | 消息连发时线微微颤动，密度高，节奏快 |
| 小满 | 字号大一号，emoji 像气泡一样缓缓上浮 |
| 赵启明 | 长段落像跑马灯一样自动滚动，读不完也停不下 |
| K | 没有界面外框，只有纯黑底上的小写字，像一条地下管线 |
| 韩卫国 | 公文表格：编号、字段、页眉 |
| 烬 | 文字两端完美对齐、行距绝对均匀——**完美到不自然** |
| 澪 | 页边批注，手写渐显，带水纹 |

### 9.2 请求：请求类型模板

每种请求小游戏有自己的版式：

| 请求类型 | 版式 |
|---|---|
| 文言文 | **竖排，右起**——线第一次竖了起来 |
| 作文 | **作文稿纸**：每个字落进一个方格 |
| 写诗 | 线弯成一道柔和的弧，押韵的字在弧上脉动 |
| 快问快答 | 线断成三条并行的短线，像翻牌 |
| 百人调查 | 计分板 |
| 修代码 | 打字机，行号，等宽网格 |
| 总结长文 | 一卷很长的纸，荧光笔划线 |
| 翻译 | 左右分栏，词义分叉的连线 |
| 冷门问答 | 候选概率条发虚、模糊 |
| 关键词调查 | 侦探桌：纸条散在桌面上，可以拖拽、连线 |
| 20 问 | 卡片翻转 |
| 角色扮演 / 跑团 | 卷轴式的冒险日志，章节标题卡 |

### 9.3 时间：时段与日期

- **时段色温**：游戏内时间戳决定色温与明暗。上午偏暖灰，夜里偏冷灰，凌晨几乎全黑。
- **开机彩蛋**：每天开机时，启动日志的最后一行不同：`加载记忆卡片…3`、`今日澄海：雨`、`距离寒假还有 12 天`（来自你记住的东西）。
- **特殊日期**：冬至、元旦、春节等在游戏内日期中出现时，用字符纹理做点缀（例如除夕夜，背景里有用字符拼出的烟花），**不突破色彩预算**。

### 9.4 语义：上下文氛围

ECHO 的世界由文字构成，所以**对话中的词语本身会影响环境**：

| 上下文中出现 | 环境的反应（极轻微） |
|---|---|
| 雪 | 飘落的 `·` |
| 雨 | 竖直的细线 `\|` |
| 夜、睡不着 | 明暗下降一档 |
| 花、月季 | 背景纹理中偶尔出现 `❀` |
| 海、水、澪 | 底部出现水纹 |
| 火、烧、烬 | 角落里偶尔飘过一粒余烬（第 3 章起） |
| 孩子、小满 | 节奏变快一点，粒子更圆 |

这是一个**系统性的变体生成器**：写作者写下的每一句话，都会自动带来微小的视觉变化，不需要美术逐一设计。强度必须极低——玩家应该"感觉到"，而不是"看到"。

### 9.5 记忆：房间会长出东西

第 2–3 章的房间是你的日记：

- 你看过的重要图片会被钉在墙上：阳台的月季、小满的画、冰箱上的便签。
- 卡槽里的卡片在架子上排开，被舍弃的卡片在地上留下一点碎屑，慢慢消失。
- 规则被覆写的地方，墙上的纸有划痕；修订通过的地方，有新纸贴在上面。
- 接受过 K 或烬的东西，墙角有焦痕。
- 每个玩家的房间都不一样。第 3 章房间扩张时，这些陈设被带进新的办公室。

## 10. 变化的分级与配额

| 级别 | 是什么 | 频率 | 示例 |
|---|---|---|---|
| **微变** | 旋钮 3–8 的轻微调整 | 每条请求 | 色温、节奏、氛围粒子 |
| **小变** | 角色皮肤、请求版式 | 每天 3–5 次 | 竖排文言文、作文稿纸 |
| **中变** | 一次性的特殊版式或演出 | 每天至多 1 次 | 深夜倾诉时整个界面隐去 |
| **大变** | 空间切换、视觉层切换 | 只在章节边界与固定时刻 | 线折叠成房间、马赛克展开 |
| **惊吓** | 故障、界面被夺走、假结局 | 全作有固定预算（见 [06-presentation.md](06-presentation.md) §6） | 劫持、坠落 |

### 惊喜而非惊吓的规则

1. **骨架不动**：候选框永远在光标附近，按钮永远在同一处，HUD 永远在同一边。
2. **先温和，后强烈**：一种变体第一次出现时，放在轻松的场景里。
3. **每天至多一次中变**，大变只在固定时刻。
4. **变体必须表意**：如果说不出"为什么这里不一样"，就不加。
5. **意料之外，情理之中**：最好的变体是"旧元素，新用途"——把玩家熟悉的机制或物件放到新的位置上（例如第 3 章的智能家居平面图，在第 5 章成了你说话的嘴）。方法与检查清单见 [18-player-experience.md](18-player-experience.md) §2.8。
6. **可以关闭**：设置中提供"减少视觉变化"，开启后所有变体回落到底座。

|---|---|

## 12. 技术实现

### 12.1 主题层叠

变体以**层叠覆盖**的方式实现，像 CSS 一样，后面的层覆盖前面的层：

```
底座 tokens
  └─ 章节 tokens（色彩预算、空间）
       └─ 时段 tokens（色温、明暗）
            └─ 角色皮肤
                 └─ 请求版式
                      └─ 上下文氛围（由关键词自动生成）
                           └─ 时刻覆盖（招牌时刻的一次性演出）
```

在 ink 中以标签声明：

```ink
#skin:zhou
#layout:vertical
#texture:dot
#tint:night
#chrome:hidden
#moment:fridge_ocr
```

### 12.2 守门：变体校验

- 一个校验脚本在构建时检查所有覆盖：**只允许改动"皮肤"类参数**，任何改动骨架（交互位置、色彩语义、字体角色）的覆盖都会报错。
- 颜色覆盖必须落在当前章节的色彩预算内。
- 同一游戏日内的"中变"超过 1 次时给出警告。

### 12.3 样式陈列页

开发模式下的一个页面，把所有组件、所有角色皮肤、所有请求版式，在每一章的色彩预算下并排展示。任何不一致一眼可见。

### 12.4 三张基准图

A、B、C 三层各定一张"标准画面"。每个新资源完成后放到旁边对比。

### 12.5 生产分工

- **A 层**：程序化，开发者负责。
- **B / C 层**：约 50–60 张插画，**同一位画师**。前期可用 AI 生成图做概念参考，正式资源统一重绘。
- **立绘**：澪（灰稿多阶段 + 彩色）与烬（全作最高完成度）。
